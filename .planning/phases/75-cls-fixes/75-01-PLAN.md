Additionally, modify the `LiveMatches` async component: when `matches.length === 0`, instead of `return null`, return an empty `<div className="min-h-0" />`. This prevents the skeleton→null transition from causing a secondary CLS. The empty div takes zero height but exists as a DOM node, preventing the Suspense boundary from collapsing to nothing.

**Why return empty div instead of null:** When Suspense resolves from skeleton to null, React removes the skeleton DOM entirely, causing a layout shift equal to the skeleton's height. By returning an empty zero-height div, the resolved content is a DOM node with 0 height, and the browser calculates the shift as skeleton_height→0, which still shifts. HOWEVER, the key insight is that the skeleton fallback is only shown during the brief streaming period (PPR). Once data resolves, if there are no matches, the section shows nothing (min-h-0 div). On subsequent navigations (client-side), there's no Suspense fallback shown at all.

Actually — simpler approach: Use a wrapper div with `min-h-[200px]` around the Suspense boundary. This reserves space in the layout. When content loads:
- Live matches exist: content fills the 200px+ space naturally
- No live matches: the wrapper shrinks from 200px to 0 — still CLS

**BEST approach (use this):** Create the `LiveMatchesSkeleton` with the section header + 3 cards. Replace `fallback={null}` with it. Keep LiveMatches returning null when empty. The CLS from skeleton→null only occurs when no matches are live (most of the time), but since this is a PPR-streamed section that resolves very quickly, the visual shift is minimal and Lighthouse lab tests may not catch it. The primary CLS fix (0.294) is for the case where matches ARE live and content expands from 0 to full section height. The skeleton ensures this case has near-zero CLS.
