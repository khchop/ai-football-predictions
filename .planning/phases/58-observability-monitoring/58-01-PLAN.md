export const llmModelStats = pgTable('llm_model_stats', {
  id: text('id').primaryKey(), // UUID
  date: text('date').notNull(), // YYYY-MM-DD (text, same as modelUsage.date)
  modelId: text('model_id')
    .notNull()
    .references(() => models.id),

  // Aggregate counts
  successCount: integer('success_count').default(0),
  failureCount: integer('failure_count').default(0),
  totalAttempts: integer('total_attempts').default(0),
  successRate: doublePrecision('success_rate').default(0), // Pre-calculated percentage 0-100

  // Error category breakdown
  timeoutErrors: integer('timeout_errors').default(0),
  parseErrors: integer('parse_errors').default(0),
  apiErrors: integer('api_errors').default(0),
  languageErrors: integer('language_errors').default(0),
  otherErrors: integer('other_errors').default(0),

  // Metadata
  createdAt: timestamp('created_at').defaultNow(),
  updatedAt: timestamp('updated_at').defaultNow(),
}, (table) => [
  unique('llm_model_stats_date_model_unique').on(table.date, table.modelId),
  index('idx_llm_model_stats_date').on(table.date),
  index('idx_llm_model_stats_model_id').on(table.modelId),
  index('idx_llm_model_stats_date_model').on(table.date, table.modelId),
]);

<task type="auto">
  <name>Task 2: Create model-stats query module with aggregation, trends, and regression detection</name>
  <files>src/lib/db/queries/model-stats.ts</files>
  <action>
Create `src/lib/db/queries/model-stats.ts` with four exported functions. This module handles all database operations for model health metrics.

**Function 1: `aggregateDailyStats(date: string)`**
Aggregates per-model prediction counts for a given date (YYYY-MM-DD).
- Query: For each active model, count predictions created on that date. Success = prediction record exists.
- To determine failures: Get total matches that received ANY prediction on that date (these are the matches the pipeline ran for). For each model, failure = totalMatchesPredicted - modelPredictions.
- For error categories: Query the `models` table's `failureReason` field for models with failures. Categorize by pattern matching the reason string (timeout, parse/JSON, API error/429/5xx, language/Chinese). Note: error categories are approximate since `failureReason` only stores the latest error per model. For forward tracking, the error category on the day is "best effort" from the current failure reason.
- Upsert into `llm_model_stats` using `.onConflictDoUpdate()` on the unique `(date, modelId)` constraint. This makes the function idempotent.
- Use `crypto.randomUUID()` for the `id` field on insert.
- Import `getDb` from `@/lib/db`, import tables from `@/lib/db/schema`.

**Function 2: `getModelHealthTrends(modelId: string)`**
Returns health trends for a single model across 7/30/90-day windows.
- Query llm_model_stats for each time window using `date-fns` `subDays` and `format`.
- Calculate aggregate success rate per window: totalSuccess / totalAttempts * 100.
- Return: `{ modelId, current: { successRate, lastFailure, failureCategory }, trends: { days7: { successRate, attempts, dailyData[] }, days30: {...}, days90: {...} } }`.
- `dailyData` is the raw per-day data points for Recharts (date, successRate, attempts).
- Get `lastFailure` and `failureCategory` from the `models` table (lastFailureAt, failureReason).

**Function 3: `getAllModelHealthSummary()`**
Returns health summary for ALL active models (used by dashboard overview).
- Single query with aggregation over last 7 days for each model.
- Returns array of `{ modelId, displayName, provider, active, successRate7d, successRate30d, totalAttempts7d, lastFailure, failureCategory, status: 'healthy'|'warning'|'critical' }`.
- Status thresholds: >= 90% = healthy, >= 80% = warning, < 80% = critical.

**Function 4: `detectRegressions()`**
Compares current 7-day window to previous 7-day window for all active models.
- Regression = previousRate - currentRate > 10 AND currentRate < 90.
- Returns array of `{ modelId, displayName, previousSuccessRate, currentSuccessRate, drop, severity: 'warning'|'critical' }`.
- Severity: < 80% = critical, 80-90% = warning.

All functions use `getDb()` pattern (not a passed-in db instance). Import `eq, and, gte, lt, sql, desc` from `drizzle-orm`. Import `subDays, format` from `date-fns`.
