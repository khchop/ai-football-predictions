Pino alert format for regressions:
```typescript
log.error({
  type: 'model-regression',
  regressions: alerts.map(a => ({
    modelId: a.modelId,
    displayName: a.displayName,
    previousRate: `${a.previousSuccessRate.toFixed(1)}%`,
    currentRate: `${a.currentSuccessRate.toFixed(1)}%`,
    drop: `${a.drop.toFixed(1)}%`,
    severity: a.severity,
  })),
}, `MODEL REGRESSION: ${alerts.filter(a => a.severity === 'critical').length} critical, ${alerts.filter(a => a.severity === 'warning').length} warning`);
```

Worker configuration:
- `concurrency: 1` (single aggregation at a time)
- `connection: getQueueConnection()` (use existing connection getter)
- Use `loggers.queue` or create child logger for model-stats context

**Startup backfill check:**
Add an `on('ready')` handler that checks if yesterday's stats exist in `llm_model_stats`. If not, trigger aggregation immediately. This handles server restarts that miss the cron window (Pitfall 4 from research).

```typescript
worker.on('ready', async () => {
  // Check if yesterday was aggregated
  const yesterday = format(subDays(new Date(), 1), 'yyyy-MM-dd');
  const db = getDb();
  const existing = await db.select()
    .from(llmModelStats)
    .where(eq(llmModelStats.date, yesterday))
    .limit(1);

  if (existing.length === 0) {
    log.info({ date: yesterday }, 'Missing stats for yesterday, backfilling');
    await aggregateDailyStats(yesterday);
    await detectRegressions();
  }
});
```
