**In `src/lib/queue/workers/scoring.worker.ts`:**

Add event-driven team content regeneration after match settlement. This ensures active teams get fresh content within hours of a match finishing (satisfying <24h refresh for active teams), while the weekly cron acts as a safety net for inactive teams.

After the existing post-match content generation block (around line 152), add:
```typescript
// Regenerate team content for both teams (non-blocking)
// Event-driven: ensures <24h refresh for active teams
try {
  const { teamContentQueue } = await import('@/lib/queue/index');
  const homeTeam = match.homeTeam;
  const awayTeam = match.awayTeam;
  if (homeTeam) {
    await teamContentQueue.add('generate_team_content', { teamName: homeTeam }, { delay: 60000 }); // 1 min delay for stats to settle
  }
  if (awayTeam) {
    await teamContentQueue.add('generate_team_content', { teamName: awayTeam }, { delay: 65000 }); // stagger
  }
  log.info({ matchId, homeTeam, awayTeam }, 'Team content regeneration queued after match settlement');
} catch (err) {
  log.warn({ matchId, err }, 'Team content regeneration trigger failed (non-blocking)');
}
```

Rationale: The success criteria states "24h refresh cycle." Weekly cron alone doesn't satisfy this for active teams. By triggering regeneration on match completion, teams that just played get updated analysis reflecting their latest result within minutes. The weekly cron remains as a safety net for teams with no recent matches (ensuring stale content eventually refreshes). This is cost-efficient: only 2 teams regenerated per match vs. all 42 teams daily.
