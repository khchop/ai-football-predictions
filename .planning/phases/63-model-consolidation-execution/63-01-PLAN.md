
**This is SIMPLER than the consolidation migration because:**
- No dedup needed (no matching base model exists for any of these 10)
- Just UPDATE model_id everywhere
- No conflicts possible (target IDs don't exist yet)

**Migration steps (within a single transaction):**

1. **Pre-validation:**
   - Count rows per old model_id across all 6 tables (models, predictions, llm_model_stats, bets, model_balances, model_usage)
   - Verify target model_ids do NOT already exist in models table (safety check)
   - Report total rows to be renamed

2. **Rename in models table FIRST** (since other tables have FK references):
   - UPDATE models SET id = new_id WHERE id = old_id
   - This must happen first because predictions.model_id references models.id
   - Use SET CONSTRAINTS ALL DEFERRED so the FK updates can happen within the same transaction

3. **Rename in all 5 FK tables:**
   - UPDATE predictions SET model_id = new_id WHERE model_id = old_id
   - UPDATE llm_model_stats SET model_id = new_id WHERE model_id = old_id
   - UPDATE bets SET model_id = new_id WHERE model_id = old_id
   - UPDATE model_balances SET model_id = new_id WHERE model_id = old_id
   - UPDATE model_usage SET model_id = new_id WHERE model_id = old_id

4. **Post-validation:**
   - Count rows with old model_ids (should be 0 across all tables)
   - Count rows with new model_ids (should match pre-validation counts)
   - Check for orphaned FKs (should be 0)
   - Verify no -syn suffixed model_ids remain in ANY table

5. **Commit or rollback based on --dry-run flag**

**Script structure (follow same pattern as migrate-consolidate-models.ts):**
- Import dotenv/config, getDb, sql from drizzle-orm
- Parse --dry-run and --verbose flags
- Print "=== Rename Synthetic Model IDs: Phase 63 (CONS-03) ===" header
- Wrap all operations in BEGIN/COMMIT transaction with SET CONSTRAINTS ALL DEFERRED
- Log per-table update counts
- Exit 0 on success, exit 1 if any validation fails

**Key difference from consolidation script:** No deduplication phase needed. This is a straightforward rename operation. No conflicts exist because the target IDs are brand new.
