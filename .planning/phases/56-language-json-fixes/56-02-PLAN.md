Step 1 -- Review current extraction coverage:
- Read response-handlers.ts EXTRACT_JSON handler: strips markdown blocks, extracts first JSON object/array
- Read prompt.ts parsePredictionResponse(): strips thinking tags, strips markdown, tries 6 JSON regex patterns, tries full parse fallback
- Read prompt.ts parseBatchPredictionResponse(): strips thinking tags, strips markdown, tries array then object extraction
- Identify gaps: does the existing code handle these patterns?
  - "Here's my prediction: {...}" (conversational prefix before JSON)
  - "Result:\n{...}" (label prefix)
  - "{...}\n\nI hope this helps!" (trailing text after JSON)
  - "Based on the analysis, I predict:\n```json\n{...}\n```" (explanation + markdown)

Step 2 -- Enhance EXTRACT_JSON handler if gaps found:
If diagnostic raw responses show patterns NOT handled by existing code, add prefix removal to the extractJsonHandler in response-handlers.ts:
```typescript
// Add before markdown removal:
// Remove common conversational prefixes
const prefixPatterns = [
  /^Here(?:'s| is) (?:the )?(?:prediction|result|json|analysis)[:\s]*/i,
  /^(?:Based on|After|Following)[\s\S]*?(?:prediction|result)[:\s]*/i,
  /^(?:Result|Prediction|Output|Response)[:\s]*/i,
];
for (const prefix of prefixPatterns) {
  cleaned = cleaned.replace(prefix, '');
}
```

ONLY add patterns that are NOT already handled by the existing JSON object regex extraction (`/\{[\s\S]*\}/`). The existing regex already matches JSON objects embedded in text -- so prefix removal is only needed if the prefix itself contains `{` or `}` characters that would confuse the regex.

Step 3 -- Verify parsePredictionResponse covers batch responses:
- Confirm parseBatchPredictionResponse has the same markdown stripping as parsePredictionResponse
- Both should handle: thinking tags, markdown code blocks, JSON patterns
- If parseBatchPredictionResponse is missing any patterns that parsePredictionResponse has, add them

Step 4 -- Validate no breaking changes:
- The extractJsonHandler MUST still return the response unchanged if no JSON is found (fallback behavior)
- parsePredictionResponse MUST still return { success: false } on truly unparseable responses
- Do NOT change the JSON pattern order in parsePredictionResponse (specific patterns before general)
- Do NOT change response_format in base.ts (per research Pitfall 3)

Step 5 -- If no gaps found:
